# NOVA EVRIKA — освітня 3D-платформа

> Інтерактивні 3D-лабораторні для української школи (6–7 клас).
> Працює у браузері, без установки. Тач (Promethean) + миша.
>
> **Live:** https://science-lab-phi.vercel.app · **Repo:** dayvan777/Science-Lab

Цей файл — «жива логіка проекту»: що це, що вже є, як воно побудоване і як ми це
робимо. Оновлюється в міру розвитку платформи.

---

## Концепція

Учень **сам**, без учителя поряд, проходить лабораторну в 3D: бере об'єкти, керує
приладами, читає показання, отримує підказки й висновки. Натхнення — **PhET** і
**learning.ua**, але нативно під сучасний браузер і тач-панель, з преміальним
візуалом, а не «алгоритмічними» симуляціями.

Принципи:
- **Самостійність** — підказки/гейтинг ведуть крізь кожен крок; помилитися важко.
- **Справжність** — фізика рахується (Rapier), 3D-органи — реальні наукові моделі,
  а не намальовані картинки.
- **Якість понад кількість** — кожна лаба доводиться до зразкового рівня.
- **Українська** мова всюди; архітектура готова до i18n пізніше.

## Дві моделі лабораторних

Платформа підтримує два архетипи — обидва живуть на одному рушії (SDK).

### 1. Процедурні фізичні лаби (маса, індукція, дифузія)
- Геометрія **процедурна** (нуль ассет-файлів) — повний контроль якості.
- **Rapier** фізика (drag-snap, баланс, пружина) або власна кінетика частинок.
- Фазова машина `intro → in-progress → finished` (+ керований розбір кроків:
  підказки-стрілки, MC-питання, гейтинг «Далі»).
- Стан — Zustand; чиста логіка/математика покрита unit-тестами.

### 2. Лаби на реальних 3D-моделях (біологія — анатомія)
- Завантаження **GLTF/GLB** через `useGLTF` (drei).
- Формат «вільний дослідник»: напівпрозоре тіло + органи, які можна
  дістати → покрутити → почитати → повернути; прогрес N/5, без гейтингу.
- Моделі — **NIH 3D / HuBMAP Human Reference Atlas** (Visible Human Male, CC-BY 4.0):
  усі в одному координатному просторі → органи самі стають на анатомічні місця.

## Архітектура

Чіткий поділ **рушій vs контент**:

```
src/
  sdk/                 ← рушій (engine). Ніколи не імпортує з labs/
    animation/         lerp, easeOutCubic/InOutCubic, springStep
    audio/             SoundManager (lazy AudioContext, mute, preload)
    guided/            StepEngine, GuidedOverlay, TaskSteps DSL, primitives
    object/            Draggable (kinematic-during-drag → dynamic-on-release)
    physics/           bodyRegistry, snapTargets, useDrag (магнітний tween)
    scene/             CinematicLighting, CameraRig, PostFX, Table, webgl, cameraStore
    ui/                Button, GlassPanel, BottomSheet, NumberInput, Loader-екрани…
    a11y/              useViewport, useReducedMotion, safeArea

  labs/<lab-id>/       ← контент конкретної лаби
    index.tsx          entry-компонент (фазова машина) + lab definition
    content/           дані: tasks/steps/scenes/organs…
    state/             Zustand-стори лаби (+ unit-тести)
    scene/             Canvas + лаб-специфічна сцена
    ui/                IntroScreen, HUD, RevealScene…

  site/                лендінг, сторінки предметів, реєстр subjects.ts
  app/                 App shell + маршрути (BrowserRouter)
```

**Правило:** `sdk/` — спільне і стабільне; нову лабу додаємо як нову теку в `labs/`
+ один запис у `subjects.ts` + маршрут. SDK поки що патерн (не npm-пакет); коли
поверхня стабілізується — можна винести у версійований пакет без реструктуризації.

## Асет-пайплайн (для лаб на 3D-моделях)

Перевірено на анатомії — рецепт для майбутніх «модельних» лаб:
- **Джерело:** NIH 3D (`3d.nih.gov`) — Public Domain / CC-BY, чиста ліцензія.
  Прямий проксі-ендпоінт `https://3d.nih.gov/api/files/<fileId>` (S3-посилання 403).
- **HRA-набір** (один Visible Human) → моделі реєструються спільно без ручного
  позиціонування. Атрибуція CC-BY обов'язкова: у `public/models/CREDITS.md` + у застосунку.
- **R3F-патерни:** клонувати кешовану `useGLTF`-сцену перед зміною матеріалів
  (`scene.clone(true)`), `useCursor` для hover (авто-очистка), важкі моделі —
  lazy + `<Loader/>` + `useGLTF.preload`. Pivot для обертання навколо центру —
  через вкладені групи (`extract → +pivot → spin → -pivot`).

## Як ми це робимо (процес = частина логіки проекту)

Кожна лаба йде строго через **superpowers**-флоу:

1. **Brainstorm** — уточнення задуму, 2-3 підходи, візуальні макети за потреби → дизайн.
2. **Spec** — `docs/superpowers/specs/YYYY-MM-DD-*-design.md` (затверджується користувачем).
3. **Plan** — `docs/superpowers/plans/YYYY-MM-DD-*.md`: бите-сайз задачі з повним кодом, TDD.
4. **Subagent-driven execution** — свіжий субагент на задачу + двостадійне рев'ю
   (відповідність спеку → якість коду) між задачами.
5. **Finish** — feature-гілка → `merge --no-ff` у master → деплой (push → Vercel).

Дисципліна: спочатку дизайн → план → код; чесний revert + переплан, якщо щось пішло
не так. Git-історія — артефакт інженерної якості.

## Якість і тестування

- **Unit-тести** покривають чисту логіку: математику, стан-машини, дані, step-engine
  (понад 460 тестів). Написані за TDD — до реалізації.
- **R3F-компоненти не тестуються unit-тестами** (потрібен реальний WebGL) — гейти
  `tsc` + `vite build`, далі ручний браузерний smoke на проді.
- Перформанс: обмежений DPR, throttle важких обчислень, контактні тіні замість HDRI
  там, де треба тримати 60 fps.
- Доступність: реальні `<button>`, `aria-*`, повага до `prefers-reduced-motion`,
  WebGL-фолбек для заблокованих/старих середовищ.

# NOVA EVRIKA — освітня 3D-платформа
## Demo Day — технічний і педагогічний огляд

---

## 30-секундний пітч

**NOVA EVRIKA** — інтерактивні 3D-лабораторні для української школи (6–7 клас), які
працюють у браузері на Promethean-панелях. Учень проходить лабу **сам, без учителя**:
бере об'єкти, керує приладами, дістає органи, читає показання — система веде його крізь
кожен крок (підказки в 3D, real-time прилади, автоперевірка).

Сьогодні це **4 готові лабораторні** у двох предметах — фізика і біологія — на спільному
рушії. Ніяких установок, акаунтів чи інтернет-залежності після першого завантаження.

## Чому це сильно

### Педагогіка
- **Самостійність:** підказки й гейтинг ведуть учня крок за кроком — помилитися важко,
  вчитель поряд не потрібен.
- **Справжність, а не відео:** у фізиці балка терезів *насправді* нахиляється під дією
  маси (Rapier), а не за анімацією; в анатомії органи — це **реальні наукові 3D-моделі**
  (NIH / Human Reference Atlas), що стоять на анатомічно правильних місцях.
- **Перетин методів/уявлень** дає розуміння: вимірювання чи будова тіла — це процес для
  дослідження, а не «картинка, яку треба запам'ятати».

### Демонстраційні моменти (що показувати)
1. **Дифузія — «жива колба»** (1 хв): одна сцена, OrbitControls, 7 місій; відповідаєш на
   питання → відкривається наступний крок. > «Це не слайди — це стан, яким керує учень.»
2. **Анатомія — дістати орган** (1 хв): клік по серцю → воно виплаває вперед і
   обертається, тіло гасне, збоку факти; «Повернути» → на місце. Прогрес 5/5.
   > «Органи самі стають на анатомічні місця — це професійний атлас Visible Human, а не
   намальовані фігурки.»
3. **Важільні терези — справжня фізика** (1 хв): кладеш яблуко, балка хилиться, підказка
   «додай ~80 г»; ставиш гирі в довільному порядку — баланс. > «Це Rapier, не скрипт.»
4. **Repo walkthrough** (1 хв): `docs/superpowers/specs|plans/` — дизайни й плани кожної
   лаби; `git log` — чітка історія «дизайн → план → виконання», чесні reverts;
   `npm run build` зелений, ≈470 тестів. > «Це продукт із перевіреною архітектурою.»

## Технічна якість (для розробника)

### Стек
React 19 + TypeScript (strict) + Vite 8 · three 0.184 / @react-three/fiber 9 / drei 10 ·
@react-three/rapier 2 (WASM) · @react-three/postprocessing 3 · Zustand 5 · Vitest 4.
Без бекенду, без CDN. Білд — статика; важкі лаби **code-split** (`React.lazy`).

### Архітектура — рушій vs контент
```
src/sdk/    ← рушій (animation, audio, guided, object, physics, scene, ui, a11y)
src/labs/   ← контент: mass-measurement, electromagnetic-induction,
              brownian-diffusion, anatomy
src/site/   ← лендінг, сторінки предметів, реєстр subjects.ts
```
Нова лаба = нова тека в `labs/` + один запис у `subjects.ts` + маршрут. Два архетипи:
**процедурні фізичні** (нуль ассетів, Rapier/кінетика) і **модельні** (реальні GLTF,
як анатомія).

### Дисципліна процесу — git history як артефакт
Кожна лаба йде через **superpowers**-флоу: brainstorm → spec → plan → subagent-driven
виконання (двостадійне рев'ю: відповідність спеку → якість коду) → merge → deploy.
Code-review реально ловить баги до мержа (напр. в анатомії: витік курсора, мутація
GLTF-кешу, прелоад 46 МБ на кожній сторінці). Спочатку дизайн → план → код; коли щось не
працює — чесний revert і переплан, без «героїчних фіксів у проді».

### Тести
- ≈470 unit-тестів (Vitest): математика, стан-машини, дані, step-engine, кінетика.
  TDD — тести перед реалізацією для чистої логіки.
- R3F-сцени не покриваються unit-тестами (потрібен реальний WebGL) → гейти
  `tsc` + `vite build` + ручний браузерний smoke.

## FAQ для пітчу

**Q: Чому не PhET (готові симуляції MIT)?**
A: PhET — давній HTML5/Java, не оптимізований під тач. Тут — нативно під тач-панелі
(snap-targets, жести), преміальна естетика, реальні наукові 3D-моделі. PhET — для
алгоритмів; це — для досвіду.

**Q: Скільки лаб і як швидко додаються нові?**
A: 4 готові (3 фізика + 1 біологія), math/history у черзі. Архітектура (SDK + реєстр
+ два архетипи) дозволяє додати лабу як окремий продуктовий цикл — дизайн → план → код.

**Q: Чому unit-тести, а не E2E?**
A: E2E для 3D drag-and-drop крихкі (WebGL-емуляція). Unit покривають 100% бізнес-логіки;
візуальне/тактильне — ручний QA на реальному пристрої + браузерний smoke на проді.

**Q: Як продаватиметься школам?**
A: Бізнес-аспект — до інвестора; технічно платформа готова до beta у школах.
